# 独立模式

本版只交付独立模式。自建中继和托管中继延后，不出现在入口，也不包含在独立运行包中。

## 用户闭环

1. 在自己的 Grok Bot 中粘贴发布页提供的安装提示词，不需要上传附件。
2. Grok Bot 下载固定版本、先校验 SHA-256，再安装并启动管理面板。
3. 从 Grok Bot 的云端桌面进入云端浏览器，打开返回的面板地址。
4. 确认云端已就绪，添加供应商 URL、协议和模型，在面板密码框中填写 API key。
5. 等待其它 Bot 空闲，点击“使用”。看到已验证的目标通道后，再发正常聊天消息验证。
6. 需要恢复时选择“官方 Grok”；等待恢复验证完成。不依靠关闭面板来恢复官方。

无需安装本机 Switch 客户端、SSH、Tailscale、另购服务器或使用我们的中继。
`127.0.0.1` 指 Grok Bot 的云端电脑，不是用户的 Windows/Mac。面板地址不要直接
复制到本机浏览器；本机仍通过原版 Grok Bot 提供的云端桌面访问。

## 必要条件

- 有可正常使用的官方 Grok Bot 账号、云端电脑和至少一次安装所需的官方对话额度。
- 云端为 Linux，Python 3.10+ 可用；切换还需要云端已有的 Node。
- 云端能访问 GitHub 发布资产和选定供应商。下载失败不会回退到未知镜像。
- 主程序及重启组件在明确支持的版本集合中。未知版本只允许管理配置，不执行切换。
- 供应商提供可从云端访问的 HTTPS API，协议为 Chat Completions、Responses 或 Messages。
  自定义 URL 不等于允许所有地址：私网、重定向等仍受安全检查约束。
- 当前只支持 API key 或无需认证的接口，未实现供应商 OAuth 登录。

独立是“不依赖本项目运营的服务”，不是脱离官方账号和云端平台。
首次安装对话可能消耗官方额度；安装和启动面板本身不调用模型。

## 修改和数据边界

安装仅写 `/workspace/grok-bot-switch-independent`，启动一个 loopback 管理进程。
不会修改 Windows/Mac 的 Grok Bot 安装，不会读取或导出其账号凭据。
安装程序不自动切换、不打补丁、不向 supervisor 写重启命令。

用户之后在面板明确点击切换时，复用已有云端事务控制器：校验版本，保留备份，
适配云端推理程序，在空闲时提交 supervisor 重启请求，并核对回执、进程身份和健康。
所以这是“本机原版不改”，不是整个系统完全无侵入。切换影响同一云端的所有 Bot。

API key 保存在用户云端的私有文件中，不回显到页面，不放入提示词或命令参数。
同一云端账号下有足够权限的进程仍可能读取文件；这不是隔离于 Grok Bot 平台的保险库。
外部推理由云端直接调用供应商，不经过本项目的服务。失败不会偷偷回落到官方。

## 运行与恢复

安装是幂等的：同一版本正在运行时返回现有面板，不重复启动，也不重新配置供应商。
云端重启后可以重新粘贴同版本安装提示词。不会添加 systemd、cron 或永久自启任务。

使用已校验的发布 ZIP 可以执行 `status`、`stop`、`start`。三个命令只管理面板。
示例：`python3 -I /实际下载路径/GrokBotSwitch-independent.zip status`。

升级前先确认没有待完成的切换，再停止旧面板，运行新版本的安装提示词。
不自动清理旧版本和密钥。不要手动删除运行目录：活跃推理或恢复可能仍引用它。
如需卸载，先在面板切回官方并确认成功，再停止面板，按实际引用检查后清理。

## 开发与验收

```sh
cd frontend
npm ci
npm test
npm run build
cd ..
python3 desktop/build_independent_bundle.py --output runtime/independent-delivery
python3 -m unittest discover -s tests -p test_independent.py
```

离线包只包含固定源文件清单和已编译前端，没有 pip/npm 安装步骤，也没有中继依赖。
ZIP 使用固定时间和未压缩存储，保证相同输入在不同构建平台得到相同 SHA-256。
生成的提示词只在对应发布资产上线且下载校验通过后才可交付用户。

安装成功、面板可访问、云端切换成功、正常聊天走外部 API 是四项独立证据。
不要把已有旧版客户端实测记录当成本版独立模式的端到端验收。
