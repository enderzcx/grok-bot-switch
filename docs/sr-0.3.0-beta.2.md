## 修复约束

- HTTP 健康与进程存活分开。状态未知不报停止；存活但失联不重复启动。
- 新描述符记录启动 ticks，防止 PID 被复用；beta.1 描述符通过已有的精确命令/用户/目录检查，保留停止旧面板的升级路径。
- 停止只发 SIGTERM 给核实归属的面板，不杀 Grok Bot，不删除 supervisor 命令，不强制 SIGKILL。
- ZIP 校验处理的是意外代码漂移；不把同一 OS 用户拥有的文件包装成抵御该用户主动攻击的隔离边界。
- 忙碌时仍禁止开始新的切换；`active-state-drift`、断联、目标或 generation 不符仍显示未确认。

## 回归与发布门槛

- Python：启动前拒绝源码和缓存 ZIP 漂移；健康检查与停止结果分离；PID/命令身份不符不得发送信号。
- Linux 实进程：暂停我们在临时目录启动的面板，确认 status=running/unhealthy、start 拒绝重复启动、stop 返回未确认；恢复调度后确认退出，再成功启动/停止。
- React：仅 busy-agent 时保留匹配的已验证回执；漂移仍拒绝。不触发任何自动切换 POST。
- 保留现有协议、控制器及权限测试。通过 PR CI 与 main CI 后发布新 tag；不覆盖 beta.1 的资产或校验值。

## 复核

修复没有新增主机切换状态机、重试框架、中继或第三方依赖。进程生命周期归安装器，主机切换归原控制器，ZIP 仍是版本完整性的单一凭据。
结构复核：PASS；测试和发布结果以 CI/Release 实际记录为准，不以此文档代替。
